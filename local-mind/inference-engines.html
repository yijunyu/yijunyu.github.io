Local Mind can serve a model through more than one engine. Engines are selected by name, and a catalogue entry may declare which engine serves it.

Why a tuned build gets its own name

An engine tuned for one model architecture is offered as its own engine identity rather than as a switch on the general-purpose one. Two reasons:

  • A catalogue entry can then name the engine it expects, so the right code path is chosen from the model rather than from a user setting that happens to be on.
  • When that build is not installed, the app can say so and fall back, instead of starting the general engine and reporting whatever it produces as though the tuned path had run.

The second point is the important one. An engine selected by a flag on another engine cannot report its own absence; an engine selected by name can.

External engine: Atomic Engine

Atomic Engine (AtomicBot-ai/atomic-engine, branch codex/expert-weight-source, MIT licence) is a fork of llama.cpp, by way of TheTom/llama-cpp-turboquant. It ships a single llama-server binary with a web chat and an OpenAI-compatible API, and it admits model, state, compute and expert buffers under one memory budget (--engine-budget-mib), streaming the MoE experts that do not fit from SSD with pread. It is not part of Local Mind; it is catalogued as an engine option for one model.

External engine: megakernel-zoo

megakernel-zoo (dangxingyu/megakernel-zoo, Apache-2.0 licence, read at commit 95e315c) is a collection of inference engines each built for exactly one checkpoint on one GPU type, written by a coding agent against a fixed evaluator that times an engine only after its logits match an FP64 reference. On NVIDIA a megakernel runs the whole decode step — every layer, the next-token choice and its feedback — as one persistent CUDA kernel with no per-operator launch and no host synchronisation between tokens. The engines are served by mkserve, an OpenAI-compatible server (also Anthropic and Ollama APIs on the Mac engine) that refuses any model/GPU pair it was not built for. It is not part of Local Mind; it is catalogued as an engine option.

HardwareNVIDIA H100 (sm_90a) and B200 (sm_100a), CUDA 13.x, compiled from source on first use; one Apple Silicon engine in MLX and run-time Metal (registry key m5max, stated minimum 36 GB). No ROCm, Ascend or other CUDA architectures; no engine for the GB10 (sm_121).
ModelsQwen3-8B, North-Mini-Code-1.0, gpt-oss-20b (H100); flint, Qwen3.8-27B, Qwen3-32B, gpt-oss-120b, Inkling-2-Mini (B200); Inkling-2-Small (4×B200); Inkling-2-Mini (M5 Max). Track A keeps the checkpoint's formats, track B allows lossless re-storage, track C is exact speculative decoding on the checkpoint's own draft head.
LimitsSteady-decode engines hold up to 8 sequences at a 2,048-token context; the two serving engines 64 sequences at 34,816. The Mac engine serves one sequence at 16,384 tokens by default, at most 32,768.
Upstream claimInkling-2-Mini track C on an M5 Max 48 GB, 2026-11-23, one greedy sequence over HTTP, 64-token prompt, 1,024 new tokens, median of six evaluations: 8.10 ms/token (123 tok/s) on synthetic prompts and 5.14 ms/token (194 tok/s) on natural text, against 73 and 120 for oMLX with DSpark and 40 for llama.cpp Q4_K_M; prefill about 1,300 tokens/s. On one B200, 1.26 ms/token with one sequence. Claimed by the publisher, not measured by us.

External engine: Splash

Splash (incoai/splash, Apache-2.0 licence; its GGUF kernels include MIT-licensed llama.cpp material; read at release 1.7.2 of 2026-11-24, commit 2afc733) is a local inference engine for Apple Silicon built around a fixed list of models. Each supported model pairs a trained DFlash2 speculative-decoding draft with Metal kernels written for its shapes; the runtime, scheduler, prefix cache (in memory and on SSD) and API are shared, and memory and context are sized automatically. It serves OpenAI Chat Completions, Responses and Completions and Anthropic Messages, with streaming, tool calls, JSON Schema output and image/PDF input, and it launches coding agents against itself (splash claude, splash codex, splash opencode). It is not part of Local Mind; it is catalogued as an engine option.

HardwareApple M3 or newer on macOS 26.4 or later, Metal only; the 27B can also prefill on the Neural Engine. No CUDA, ROCm or Ascend backend. Of the machines on this site only the M4 mini (M4, macOS 26.5.2) meets the stated chip and OS requirement; the M1 Ultra and the M2 Max are below M3, and the GB10, AMD and Ascend boxes have no backend.
ModelsQwen3.8-27B, Qwen3.6-35B-A3B, Ornith-1.5-122B, Qwen3.8-Flash-Next, Flint and Inkling-2-Mini, each as unsloth GGUF (1–8-bit, including UD mixes) or MLX 4-bit, with the family's draft chosen automatically; Ternary Bonsai 2 27B in PQ2_0; Inkling-2-Mini also from its release checkpoint (text only). MLX affine 2–8-bit, mxfp4, mxfp8 and nvfp4 load; whole-BF16/F16 GGUFs are refused. Rows already in this catalogue for these families: Qwen, Ornith, Inkling, Flint, Ternary Bonsai; none of them was measured through Splash.
Install and serveDesktop app (Splash.dmg) or brew install incoai/tap/splash, then splash serve --model unsloth/Qwen3.8-27B-GGUF:UD-Q4_K_M; the first run downloads the model and its draft. Local files: --model-dir <gguf or dir> --draft-model <draft dir>. Options include --max-memory, --max-context (up to 1M), --kv-format bf16 (default INT8 KV) and --disable-ane. It listens on 127.0.0.1:8000 without authentication by default, the same port as Local Mind's engine, so the two cannot serve side by side on default settings.
Upstream claimSplash 1.0 on an M5 Pro (16-core GPU, 48 GB), SPEED-Bench coding prompts over HTTP: short-prompt decode 210 tok/s on Qwen3.6-35B-A3B and 74 on Qwen3.8-27B; 32K-prompt prefill 2,011 and 363 tok/s; four concurrent short prompts 357 and 170 tok/s aggregate. Qwen3.8-Flash-Next Q2_0 on an M5 Pro (20-core, 64 GB): 95 tok/s decode and 1,312 tok/s prefill, 1.3× Strata on the same GGUF. Against llama.cpp on the same UD-Q4_K_M files (BF16 KV, no ANE): 27B 74 vs 16 tok/s on an M5 Pro and 92 vs 17 on an M3 Max; 35B-A3B 175 vs 69 and 209 vs 66. On a 24 GB Mac: 43.5 tok/s for the 27B UD-IQ3_XXS and 145 for the 35B-A3B UD-Q2_K_XL. Upstream-claimed, not measured by us.

The cheapest host that meets the requirement is the M4 mini; at 16 GB it is below the 24 GB the publisher documents as its smallest configuration, so only its smallest files (the 7.2 GB Ternary Bonsai 2 PQ2_0, or an Inkling-2-Mini 2-bit GGUF) are plausible there, and whether they fit with Splash's memory reserve is untested.

Availability

Engine availability depends on which builds are installed on the machine. The app shows an engine as available only when the binary that implements it is present. The named-engine mechanism described here is on a development branch and is not in a released or TestFlight build.
